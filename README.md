# 本地 AI 视频工作台 v1.10 完整版

把故事想法、人物设定、分段提示词和视频制作放在同一个本地网页里。

这是面向 Windows 的本地创作工作台，当前版本编号为 **v1.10 完整版**，固定保存于2026-11-01。仓库提供工作台源码、预设和工作流 JSON，不包含模型、用户项目或生成素材。默认调用本机模型服务；安装代码本身并不等于安装好了模型。

适合已经有本地模型环境、希望把故事到视频的制作过程放进同一个界面的创作者，也适合希望修改预设、指令词或工作流的开发者。只想下载一个文件就直接出片的使用者，需要先完成下面的环境配置。

[GitHub 仓库](https://github.com/bilibili-laona/ai-short-drama-workbench) · [版本记录](CHANGELOG.md) · [MIT 许可证](LICENSE)

## 让 AI 帮你接入本地模型

下载源码包并解压，把整个文件夹交给 Codex 等能读取和修改本地文件的 AI 工具，要求它先读根目录的[AI接入说明](AI接入说明.md)及[详细接口文档](docs/LOCAL_MODEL_INTEGRATION.md)，再检查你的模型服务与配置。根目录的 `AGENTS.md` 也提供了接入入口和操作边界。

这是让 AI 配置**工作台调用的本地模型接口**，不是要求把 Codex 自身切换成本地模型。AI 应先识别现有环境、检查协议和节点、备份配置，再做小规模验收；遇到不兼容必须说明缺什么，不能假装已经接好。不同模型或工作流可能仍需单独适配，源码包不附带权重、显卡运行环境或私人配置。

## 能做什么

- 输入一句话或一段故事想法，先生成文字，再检查、修改。
- 编辑人物卡、场景卡，生成对应的设定图。
- 调整人物的头身比例、体型、五官、发型与服装；在设置页修改预设和指令词。
- 检查剧本和视频分段，编辑每段的提示词与参考素材。
- 调用本地视频工作流逐段生成，再用 FFmpeg 合成成品。
- 在同一项目里制作续话，复用人物和场景设定。
- 上传参考视频，独立替换人物或人物加背景，输出完整原声视频及左右对比。

人物、姿势、服装、动作、台词和接缝的最终效果取决于模型，仍需要人工验收。本仓库不承诺精确头身数、完全一致的人脸或无缝视频。

## 一次制作怎么进行

```text
故事想法
   ↓
① 生成文字：剧本 → 人物卡、场景卡 → 视频分段
   ↓ 检查文字、人物选项和分段
② 生成图片：人物设定图、场景设定图
   ↓ 检查外观，也可以上传自己的参考图
③ 生成视频：分段提示词 → 分段视频 → 合成成片
   ↓
逐段验收、重做或下载；需要续写时新建下一话
```

这三个按钮是不同的制作终点。直接点击后一步，程序会尝试补齐尚未完成的前置步骤；它仍依赖模型和配置正常工作。先检查文字和图片，可以较早发现问题。

| 按钮 | 会做什么 | 什么时候用 |
| --- | --- | --- |
| ① 生成文字 | 根据故事想法写剧本，整理人物与场景，生成导演分段 | 先检查故事和角色是否符合预期 |
| ② 生成图片 | 补齐必要文字，生成人物和场景设定图 | 先确认人物外观与环境 |
| ③ 生成视频 | 补齐必要文字和图片，写分段提示词、生成视频并合成 | 设定已经确认，准备进入耗时的出片阶段 |

## 功能详解

### 故事与项目设定

每个项目有独立的故事、人物、场景和生成结果。故事想法可以是一句话、一段口述转成的文字，或更详细的情节说明；这里的“口述”指输入内容的表达方式，不代表工作台内置了麦克风转写功能。

可按项目选择世界类型、画风、视点、内容倾向、附加要求，以及视频的分辨率档、采样步数和画幅。当前默认是西方、网红自然感、电影第三人称、0.4 档和 10 步。

正文节奏保留“紧凑”和“舒缓”：主要影响文字的叙述、对白和动作展开方式。每段视频如何拆分、安排多少秒，由导演分段和手动编辑共同决定，不能把正文节奏当成视频播放速度开关。

### 人物卡与人物设定图

先根据故事设计文字人物卡，再根据人物卡生成图片提示词和设定图。用户可以先扫一遍人物卡，也可以逐项修改后再出图。

首图不把自动体型标签扩写为额外参数。身高留空、比例和身材保持原设定时，沿用人物原始事实；填写明确身高或手动覆盖后，下次出图加入对应要求。

| 维度 | 当前内置内容 | 控制重点 |
| --- | --- | --- |
| 头身比例 | 男女共用 8 档 | 头部相对大小、躯干和四肢的纵向比例 |
| 体型 | 男 8 档、女 8 档 | 身体宽厚、脂肪与肌肉等外形特征 |
| 五官骨相 | 男 12 类、女 12 类 | 脸部结构与外观特征 |
| 发型 | 男 24 种、女 32 种 | 头发的长短、轮廓和造型 |
| 服装 | 按世界类型组织的预设 | 衣着风格与身份表达 |
| 年龄、性别、外观文字 | 人物卡中编辑 | 人物身份与个体描述 |

这些是内置预设数量，用户修改预设后数量可以变化。比例选项中的造型名称不代替人物卡年龄，实际图片也不保证精确达到某个头身数。

人物图默认通过设定板展示同一人物的多个视角和脸部特写。姿势和版式由设置页同一份展示模板负责；主指令引用所选模板，要求完整放在最终提示词最前面。普通男女模板在“普通姿势＋版式”中编辑，尺度专用模板在“尺度人设图”中编辑。保存后下次生成提示词生效，已有旧提示词和图片保留；生成后仍需人工检查。

人物卡的“完全重新设计”以当前选项和文字为依据：先保存人物卡，清除该人物旧的手写出图提示词覆盖，再生成并采用新图。它并不是要求设计师重新随机选择人物选项。

提示词面板里的“按这份提示词出图”会保存当前提示词，并据此重新生成一张图，文字没有修改也可以再次生成。手写提示词与人物卡可能不同；希望重新以人物卡为准时，使用人物卡上的重新设计入口。

改一个选项，表达的是只改这一项的设计要求；文生图模型重新采样时，其他视觉细节仍可能变化。这不等同于像素级局部编辑或绝对锁脸。

### 场景与参考图片

主流程可分别选择人物与场景使用的 Krea2/MOSS 模型；例如人物用 Krea2、场景用 MOSS。选择作用于后续新素材，已提交任务保留自己的模型与尺寸快照。MOSS 的2倍档为1360×768底图、2720×1536成品；4K档为1920×1088底图、3840×2176成品。实际尺寸以生成记录为准。

从故事中整理场景卡，并生成为视频使用的场景设定图。人物图和场景图可以分别上传、替换和采用。图片会绑定到指定人物或场景，供后续分段选择引用。

在成品页可以查看设定图、生成新版本、上传替换、导出，并在“换一版”中查看已有版本。已经生成的视频不会因为参考图换了就自动变成新版本，需要重新生成相关视频段。

### 剧本与手动分段

剧本页可以修改当前这一话的内容，编辑后自动保存，并显示保存状态。视频分段可以单独调整地点、出场人物、时长、镜头说明和分时段动作，也可以在某段后添加一段或删除段落。

修改剧本可能使现有分段被标记为过期；再次自动分段会替换手动编辑的分段。建议先定剧本，再细调分段，并留意页面上的过期和重分提示。

### 分镜视频与提示词

分镜视频页按段查看视频、提示词与参考图。可以让模型根据一段拍法描述编写提示词，也可以直接编辑。出过片后，还能查看实际发给视频模型的文本，包括参考编号与接力描述。

支持选择接下来要生成的段数、生成单段、重新生成不满意的段落，以及调整每段使用的人物和场景参考。已有结果用于人工检查，不要求发现问题后重做整部作品。

后续段可以结合前段末帧作衔接参考。它有助于延续画面，也可能把旧衣着、旧姿势等状态继续带入，所以换衣、换景和动作衔接仍需检查。

分辨率档按像素量划分，不是百分比缩放。例如当前 H3 配置中，16:9 的 0.4 档为 864×480，0.7 档为 1120×624，1.0 档为 1376×768。提高档位或步数会增加计算成本，最终效果取决于模型和参数。

### 长篇漫画与可选局部修图

输入画风、人物和故事，依次规划全书、规划本章，再按页生成。可从已有故事项目复制文字人设，或手动填写；来源保存为独立快照，原项目后续修改不会静默改写漫画。逐格保存服装、持物、伤势和位置状态；这些是叙事状态，不是对成图的自动视觉确认。

可暂停后续页、继续未完成页面、修改分镜与对白、重做单页并保留旧版本。导出采用当前有效版本，修改后尚未重做或衔接过期的页面会提示处理。当前整页生成使用 MOSS。

配置 Qwen Image 2.1 后，可为人物上传参考图，在当前采用页上框选局部并生成修图候选，再预览、比较和手动采用。框外保留原图像素，选区内部由模型重新生成。它不自动修改剧情，不保证锁脸、零错字或所有接缝自然；未配置编辑模型也可使用 MOSS 漫画生成。

### 成品、历史与续话

“成品”页集中查看人物图、场景图、分镜段视频和合成成片。可以勾选部分段落合并，也可以合并整话，并下载生成的成片。

“历史”页可以按图片、视频、来源等筛选，查看已记录的提示词并复制，把选中的生成结果保存到项目。

继续讲同一个故事时，在剧本页新建下一话，填写“这一话讲什么”，生成并检查该话文字和分段，再进入图片或视频制作。已有角色与场景可以复用；新出现的角色或地点仍需要整理对应设定。各话共享设定不代表动作、道具和服装状态永远完全正确，续话前仍需检查。

### 预设、指令词与运行状态

设置页提供独立的人物预设编辑区，可以添加、修改和删除选项。比例、男女体型、五官、发型、姿势、服装等预设用于后续生成；修改预设不会自动重做旧素材。

工作流指令词按阶段组织，可以查看和修改每一步发给文字模型的指令，并查看它引用的预设。界面保存前会为指令词和预设留下备份。

全局默认用于新建项目。任务、进度和日志用于查看当前执行状态；界面有取消入口。“清理缓存”会取消全部生成和排队、释放本地模型、清除残留占用并把任务数与进度归零；旧任务不会自动恢复。故事、人物卡、素材、成品、草稿、配置和历史记录保留。显存显示实际占用，桌面本身使用的显存不会假装归零。

## 运行环境

现有流程在 Windows 上使用；其他系统尚未验证。

| 用途 | 外部程序或模型 | 默认服务地址 |
| --- | --- | --- |
| 写故事、设计人物、写提示词 | llama.cpp 的 llama-server + 兼容的 Qwen GGUF 模型 | 127.0.0.1:8080 |
| 人设图、场景图 | ComfyUI + 对应 Krea2/MOSS 工作流、模型及节点 | 127.0.0.1:8188 |
| 漫画局部修图（可选） | 已运行的ComfyUI + Qwen Image 2.1模型、编码器、VAE及编辑节点 | 127.0.0.1:8188 |
| Anima独立出图（可选） | 同一ComfyUI服务 + `models/anima_workflow.json`对应模型与节点 | 127.0.0.1:8188 |
| 视频 | ComfyUI + 对应 MiniMax H3 工作流、模型及节点 | 127.0.0.1:8190 |
| 视频读取与合成 | FFmpeg、ffprobe | 加入 PATH |
| 工作台 | Python 3.12+、Pillow、zhconv | 127.0.0.1:8853 |

Python 客户端与工作流 JSON 在 `models/` 中，它们不是模型权重。各模型和节点需另行安装，并遵守各自的使用许可。显存与速度取决于所选模型、分辨率和硬件，不保证普通电脑可以直接出片。

## 安装

下载源码并解压到可写目录。在该目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
```

编辑 `config.json`，把示例路径改成自己的真实路径。不要填写其他人的路径，也不要提交这个文件。

```json
{
  "llama_server_exe": "X:/llama.cpp/llama-server.exe",
  "model_gguf": "X:/models/qwen.gguf",
  "mmproj_gguf": "X:/models/mmproj.gguf",
  "llama_log": "X:/llama.cpp/workbench.log",
  "llama_err_log": "X:/llama.cpp/workbench.err.log",
  "comfy_dir": "X:/ComfyUI",
  "comfy_output": "X:/ComfyUI/output",
  "h3_root": "X:/MiniMax-H3",
  "legacy_root": ""
}
```

`comfy_dir` 和 `h3_root` 必须匹配客户端预期的目录结构，不是任意一个安装目录都能直接接入。启动方式详见 `models/krea_client.py`、`models/h3_client.py`。使用自行管理的服务时，可以分别通过 `V41_QWEN_URL`、`V41_COMFY_URL`、`V41_H3_URL` 设置地址；仍需检查工作流节点与模型文件名是否匹配。

启动：

```powershell
.\.venv\Scripts\python.exe server.py
```

打开 `http://127.0.0.1:8853/`。首次启动会创建空的数据目录，不会导入作者的私人项目。

如使用双击启动脚本，需要 `python` 命令已指向装好依赖的环境；否则请使用上面的虚拟环境命令。

## 建议使用顺序

1. 新建项目，写故事想法，检查世界类型、画风和视点。
2. 先生成文字，检查故事和人物卡。
3. 需要时先出设定图，由自己检查外观。
4. 检查剧本和分段，确认每段提示词及参考素材。
5. 生成视频，逐段检查，再合成成品。

默认项目设置为：西方、网红自然感、电影第三人称、0.4 档、10 步。可以按项目修改。正文节奏有手动选项，视频分段并不等同于这个节奏选项。

## 安全与隐私

- 发布版默认只监听本机。没有面向公网的登录和权限系统，不要端口映射，不要用作公网服务。
- `config.json`、`data/`、`outputs/`、缓存、日志、备份和模型权重全部排除在 Git 之外。
- 内置工具只发布明确选定的源码、默认模板和工作流；私人聊天、虚拟人物资料、旧项目、图片与视频不发布。
- 若自己把模型地址改成远程服务，输入及参考素材可能发送到该服务；这不属于纯本地运行。
- 模型切换可能停掉其他本地模型服务。不要在重要的其他推理任务进行中使用自动切换。
- 对生成内容自行验收；人物年龄与内容边界仍需检查。不要移除年龄保护。

## 已知限制与常见问题

- Windows 是当前使用环境；macOS、Linux 和其他模型组合尚未完成适配验证。
- 工作流依赖特定节点、模型文件名和目录结构，不能把任意 ComfyUI 地址填进去就保证兼容。
- 新视频链已检查必需的已采用参考图文件；文件存在不代表图片内容正确，出视频前仍请人工确认人物和场景。
- 动作迁移不是骨骼级或逐帧锁定：接缝、动作、道具和背景可能偏移。上传素材后仍需填写特征，尚未实现自动识图描述。
- 衣着、姿势、人物脸部、动作、对白、节奏和段间衔接可能偏离提示词。可以修改提示词和参考、重做对应段落，但不保证一次出片全部正确。
- 文字修改、预设修改、图片替换不会自动重画已有成品；重新分段也可能覆盖手动分段。
- 高分辨率、大模型和长视频需要更多显存与等待时间，当前不承诺统一的最低显存或固定生成速度。
- 游戏模式会影响模型占用；模型切换也可能停止其他本地模型服务。
- 本版没有自动更新器、云端账号系统或公网部署鉴权，也不包含模型下载与安装程序。
- 单独的语音核对不是本版主流程要求的人工操作步骤，也不是本版重点介绍的功能。
